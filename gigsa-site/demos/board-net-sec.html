🔌 통신 시스템 & 네트워크 장비

데이터를 목적지까지 전달하기 위해 OSI 계층별로 사용되는 장비들의 역할입니다.

L1
물리 계층 (Physical)

📡 리피터 (Repeater)

디지털 신호를 증폭시켜 전송 거리를 연장하는 장비. (단순 신호 증폭기)

🐙 더미 허브 (Hub)

여러 대의 컴퓨터를 별형(Star)으로 연결. 한 곳에서 들어온 신호를 모든 포트로 브로드캐스팅(전달).

L2
데이터 링크 (Data Link)

🌉 브리지 (Bridge)

두 개의 LAN을 연결. MAC 주소를 기반으로 프레임을 필터링 및 포워딩함.

🎛️ L2 스위치 (Switch)

다중 포트 브리지. 목적지 MAC 주소만 보고 해당 포트로만 데이터를 전송하여 충돌(Collision)을 막음.

L3
네트워크 (Network)

🚥 라우터 (Router)

서로 다른 네트워크 간에 데이터를 전송. IP 주소를 읽고 가장 빠른 최적의 경로(Routing)를 설정함.

🚪 게이트웨이 (Gateway)

전혀 다른 프로토콜 구조를 가진 네트워크를 연결해주는 출입문 역할. (보통 L3 이상에서 동작)

🚥 흐름 제어(Flow) 및 오류 제어(ARQ)

데이터 링크/전송 계층에서 신뢰성을 보장하기 위해 수신측 상태에 맞춰 전송하고, 에러 시 재전송하는 기법입니다.

흐름 제어 (Flow Control)

정지-대기 (Stop-and-Wait)

🛑

패킷을 하나 보내고, 수신측에서 ACK(수신 확인)가 올 때까지 무조건 기다렸다가 다음 패킷을 보내는 가장 단순한 방식. (비효율적)

슬라이딩 윈도우 (Sliding Window)

🪟

수신측이 처리할 수 있는 버퍼 크기(윈도우)만큼 ACK를 기다리지 않고 연속해서 패킷을 쏟아붓는 방식. (TCP의 기본 흐름 제어)

🔄 자동 반복 요청 (ARQ) 3대장

오류 발생 시 송신측에 재전송(Retransmission)을 요구하는 기법입니다.

1. Stop-and-Wait ARQ

가장 기초. 1개 보내고 ACK(성공) 또는 NAK(에러)가 올 때까지 기다림. NAK가 오면 그 1개를 다시 보냄.
1번 전송 ➔
➔ ACK 수신
2번 전송 ➔
➔ NAK 수신 (에러)
2번 재전송 ➔

2. Go-Back-N ARQ 가장 많이 씀

연속해서 쫙 보내다가, 2번 패킷이 에러나면 2번부터 그 뒤에 보냈던 모든 패킷(3, 4, 5..)을 싹 다 다시 보냄.
1, 2, 3, 4번 연속 전송 ➔
➔ 2번 패킷 에러 발생!
3, 4번은 정상 도착했지만 무시됨
2, 3, 4번 전부 재전송 ➔

3. Selective Repeat ARQ

에러가 발생한 딱 그 패킷(선택적)만 다시 보냄. 복잡하지만 네트워크 효율은 가장 좋음.
1, 2, 3, 4번 연속 전송 ➔
➔ 2번 패킷 에러 발생!
3, 4번은 버퍼에 저장해둠
2번만 콕 찝어 재전송 ➔

📡 LAN 통신 방식 및 IEEE 표준

유선과 무선의 매체 접근 제어 방식(CSMA)과 주요 IEEE 802 규격을 완벽 비교합니다.

🔌

CSMA/CD

Collision Detection (충돌 검출)

  • 적용 유선 이더넷 (Ethernet) 환경에서 사용
  • 원리 선이 비어있는지 확인(CS) 후 전송 ➔ 충돌이 꽝! 일어나면 그걸 감지(CD) ➔ 잠시 대기(랜덤 시간) 후 재전송
  • 특징 선으로 직접 연결되어 있으니 충돌을 바로 알아챌 수 있습니다.
📶

CSMA/CA

Collision Avoidance (충돌 회피)

  • 적용 무선 랜 (Wi-Fi) 환경에서 사용
  • 원리 공기가 비어있는지 확인 ➔ 충돌을 감지하기 힘드니까 아예 사전에 사인을 주고받아(RTS/CTS) 충돌을 회피(CA)함.
  • 특징 공기 중에서는 충돌이 나도 파악하기 힘들기 때문에 충돌을 미연에 방지하는 것이 핵심입니다.

성형 (Star)

버스형 (Bus)

💍

링형 (Ring)

이웃 기기끼리 고리 모양 연결. 단방향 전송 (토큰 패싱 사용)

모두가 서로 연결. 신뢰성 최고! 비용도 최고! (회선 수: n(n-1)/2)

CYBER SECURITY

접근 통제 3원칙(MAC, DAC, RBAC)과 암호 알고리즘 총정리

🛡️ 접근 통제 정책 (Access Control)

누가 어떤 데이터에 접근할 수 있는지 권한을 부여하는 세 가지 방식입니다.

MAC

Mandatory Access Control
(강제적 접근 통제)

👮

"자원의 보안 등급과 사용자의 권한 등급을 비교해 통제한다!"

  • • 주체: 시스템 (관리자)
  • • 기준: 보안 등급 (Top Secret, Secret 등)
  • • 특징: 가장 강력함. 군대나 정부 기관에서 주로 사용.

DAC

Discretionary Access Control
(임의적 접근 통제)

🧑‍💻

"이 파일은 내꺼니까, 내가 홍길동한테 권한 줄게!"

  • • 주체: 데이터 소유자 (Owner)
  • • 기준: 사용자의 신원 (ID)
  • • 특징: 소유자가 권한을 마음대로 부여/회수. 유닉스/리눅스 파일 권한이 대표적.

RBAC

Role-Based Access Control
(역할 기반 접근 통제)

👔

"과장 역할에게는 수정 권한을, 인턴 역할에게는 읽기 권한을!"

  • • 주체: 중앙 관리자
  • • 기준: 조직 내 역할 (Role)
  • • 특징: 인사이동이 잦은 기업 환경에 적합. 권한 관리가 매우 용이함.

암호화 키 = 복호화 키. (비밀키 암호화)

DES AES SEED (국산) ARIA (국산) IDEA

비대칭키 (Asymmetric Key)

암호화 키(공개) ≠ 복호화 키(개인). (공개키 암호화)

RSA ECC (타원곡선) ElGamal

단방향 알고리즘 복호화 X

해시 (Hash)

입력 데이터의 길이에 상관없이 고정된 길이의 해시값을 출력합니다.
주로 비밀번호 저장이나 데이터 무결성(위변조 방지) 확인에 사용됩니다.

SHA (SHA-256 등) MD5 HAS-160 (국산)
💡 합격 핵심 팁

시험 문제에서 "암/복호화 키가 같다"면 대칭키(AES 등)를, "무결성 확인"을 묻는다면 해시(SHA 등)를 고르세요!
