* 외래키(Foreign Key): 다른 릴레이션의 기본키를 참조하는 속성. 테이블 간의 관계를 연결합니다.

데이터 무결성 3원칙

🛡️

개체 무결성 (Entity Integrity)

테이블의 기본키(PK)는 절대 NULL값을 가질 수 없으며, 중복된 값을 가질 수 없습니다.

🔗

참조 무결성 (Referential Integrity)

외래키(FK)의 값은 참조하는 테이블의 기본키 값과 반드시 일치하거나 완전히 NULL이어야 합니다.

📝

도메인 무결성 (Domain Integrity)

특정 속성의 값은 그 속성이 정의된 도메인(범위, 데이터 타입)에 속한 값이어야 합니다. (예: 성별은 '남/여'만 가능)

🧮 관계대수와 관계해석

원하는 데이터를 찾기 위한 '절차적' 기법(대수)과 '비절차적' 기법(해석)입니다.

순수 관계 연산자 (관계 대수)

"어떻게(How)" 데이터를 구할 것인가를 연산자의 나열로 기술하는 절차적 언어

관계 해석 (Relational Calculus)

원하는 데이터가 "무엇(What)"인지만 선언하고 "어떻게(How)" 구하는지는 시스템에 맡기는 비절차적 언어입니다. 튜플 관계해석과 도메인 관계해석이 있으며, 제안자는 E.F. Codd (코드) 입니다.

🔗 함수적 종속 (Functional Dependency)

X의 값을 알면 Y의 값을 무조건 알 수 있을 때, "Y는 X에 함수적으로 종속된다" (X → Y) 라고 합니다.

🔄 트랜잭션 상태 및 절차형 DB

데이터베이스의 논리적 작업 단위(트랜잭션)의 생명주기와 절차적 프로그래밍 모듈입니다.

트랜잭션 상태 전이도

활동 (Active)
부분 완료
완료 (Committed)
실패 (Failed)
철회 (Aborted)

절차형 데이터베이스 (Procedural DB)

SQL에 흐름 제어(조건, 반복문)를 추가하여 DBMS 서버 내에서 직접 실행되도록 구성한 프로그램 모듈입니다.

⚡

트리거 (Trigger)

INSERT, UPDATE 등의 데이터 갱신 이벤트 발생 시 자동으로 호출되어 실행되는 프로그램.

📦

저장 프로시저 (Stored Procedure)

여러 쿼리를 하나로 묶어 모듈화하고, 필요할 때 CALL 명령어로 직접 호출하여 일괄(Batch) 처리.

🔁

사용자 정의 함수 (UDF)

프로시저와 비슷하지만 반드시 Return 문을 통해 단일 값을 반환하며, 주로 SELECT문 내부에서 사용.

🔒 로킹 메커니즘 & 파티셔닝

동시성 제어를 위한 로킹(Locking)과 대용량 데이터 관리를 위한 파티션 기술입니다.

인터랙티브 로킹 시뮬레이터

로킹(Locking) 단위의 크기를 조절해보며 데이터베이스 성능의 상관관계를 확인하세요.

작음 (레코드/행) 로킹 단위 크기 큼 (데이터베이스)
병행성 (동시성) 수준 보통

로킹 단위가 작으면 여러 트랜잭션이 동시에 작업하기 좋습니다.

오버헤드 (관리 비용) 보통

로킹 단위가 작을수록 관리해야 할 락(Lock)의 수가 많아져 시스템 부담이 커집니다.

시험 핵심 요약 📝

로킹 단위가 작아지면 병행성은 증가하지만, 관리 오버헤드도 증가합니다.

파티션(Partition)의 종류

Range

범위 분할

지정한 범위를 기준으로 분할 (예: 2023년 데이터, 2024년 데이터)

List

목록 분할

특정 값의 목록을 명시하여 분할 (예: 서울, 부산, 대구 등 지역별)

Hash

해시 분할

해시 함수의 결과값에 따라 균등하게 분할. 특정 데이터가 어디 있는지 예측 불가.

Composite

조합 분할

위의 분할 기법을 2개 이상 결합 (예: 연도별 Range 후 다시 지역별 List)

데이터 전환
(Data Migration)

기존 시스템의 데이터를 새로운 시스템의 목적에 맞게 변환하여 적재하는 일련의 과정(ETL)입니다.

E
추출 (Extraction)
기존 원천 시스템에서 필요한 데이터 획득
T
변환 (Transformation)
목적 시스템 구조에 맞게 매핑 및 데이터 정제
L
적재 (Loading)
변환된 데이터를 새로운 DB 시스템에 삽입
