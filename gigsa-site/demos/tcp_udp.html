전송 계층의 두 라이벌:
TCP vs UDP

안전하고 정확하게 보낼 것인가(TCP), 아니면 빠르고 거침없이 쏟아낼 것인가(UDP).
정보처리기사 4계층 핵심 프로토콜의 작동 방식을 눈으로 확인하세요.

TCP

Transmission Control Protocol

📦
  • 연결형 통신 전 3-Way Handshake로 논리적 연결을 수립합니다. (가상 회선 방식)
  • 신뢰성 데이터의 순서를 보장하고, 분실 시 재전송(Retransmission)합니다.
  • 제어 송수신 속도를 맞추는 흐름 제어, 네트워크 혼잡을 막는 혼잡 제어 기능이 있습니다.
📌 주요 활용: 웹(HTTP), 이메일(SMTP), 파일 전송(FTP) 등 데이터 유실이 없어야 하는 서비스

UDP

User Datagram Protocol

🚀
  • 비연결형 사전 연결 없이 수신자의 수신 가능 여부와 무관하게 데이터를 일방적으로 던집니다.
  • 비신뢰성 순서를 보장하지 않으며, 패킷이 중간에 유실되어도 재전송하지 않습니다.
  • 초고속 복잡한 제어 기능과 헤더가 없어 오버헤드가 적고 속도가 매우 빠릅니다.
📌 주요 활용: 실시간 스트리밍(YouTube), 온라인 게임, 화상 회의, DNS 등 속도가 생명인 서비스

프로토콜 헤더(Header) 구조 비교

TCP는 신뢰성을 위해 무겁고 복잡하며, UDP는 가볍고 단순합니다.

TCP Header (보통 20 Bytes ~ 최대 60 Bytes)

Source Port (16 bit)
Destination Port (16 bit)
Sequence Number (32 bit) - 순서 제어
Acknowledgment Number (32 bit) - 수신 확인
Data Offset
Reserved
Flags (6 bit)
Window Size (16 bit) - 흐름 제어
Checksum (16 bit)
Urgent Pointer (16 bit)

UDP Header (고정 8 Bytes)

Source Port (16 bit)
Destination Port (16 bit)
Length (16 bit)
Checksum (16 bit)

💡 정보처리기사 기출 포인트

  • • TCP 헤더의 Flags(제어 비트): URG, ACK, PSH, RST, SYN, FIN 6가지 플래그로 연결 상태를 제어합니다. (특히 연결 설정 시 SYN, 연결 해제 시 FIN 사용)
  • • 흐름 제어(Flow Control): 수신자의 처리 속도에 맞춰 송신 속도를 조절하는 것으로, TCP 헤더의 Window Size를 사용합니다. (슬라이딩 윈도우 방식)
  • • UDP는 순서 번호(Sequence Number)나 수신 확인(Acknowledgment Number) 필드가 아예 존재하지 않음을 확인할 수 있습니다.
